# NAS 세션 무효화와 진단

[English](2026-11-16-web-session-logging.md) | **한국어**

사용자 요구: NAS 로그인 실패 시 웹 사용자를 로그아웃시켜야 하며, 로그에는 실패한 요청과 실제 NAS 오류가 드러나야 한다. Aside에서 새로 로그인한 뒤 읽기는 성공했다. 원래 실패한 브라우저에서는 진단 정보 없이 NAS_API_ERROR가 반환되었으므로 정확한 상위 서버 원인은 입증되지 않았다.

- [x] 일시적인 만료, 로그인 유지 읽기 재시도 1회 후 반복되는 만료, 네트워크/API 오류를 포함한 모든 NAS 재로그인 실패, 쿠키 제거 및 토큰 재사용 거부에 대한 회귀 테스트를 추가한다.
- [x] 입증된 NAS 인증 실패 시 해당 자격 증명/세션을 폐기하고 쿠키를 지운다. 초안을 보존한다. 교체 전 요청이 늦게 도착해 새 쿠키를 제거하지 않도록 알 수 없는 토큰에 대한 응답은 쿠키를 삭제하지 않는 동작을 유지한다.
- [x] macOS처럼 NAS 로그인과 함께 인증된 API 탐색을 유지한다. 만료된 세션은 재탐색에 의존하지 않고 실제 API로 전달한다. 최상위 응답 오류뿐 아니라 중첩된 API 실패 코드도 해석한다.
- [x] 서버가 생성한 ID로 요청 완료, NAS 작업, 오류 및 무효화를 연결하고 소요 시간과 정제된 진단 정보를 포함한다. 자격 증명, 노트 데이터 및 쿼리 문자열은 제외한다. 일반 Uvicorn 접근 로그는 비활성 상태로 유지한다.
- [x] 프런트엔드 인증 만료 알림을 중앙화하여 그래프와 첨부 오류 처리기가 로그인된 화면을 유지하지 못하게 한다.
- [x] 전체 테스트/빌드, 로그인 유지 켜기/끄기 상태에서 Aside로 모의 NAS 만료, 검토 및 다중 아키텍처 이미지 게시를 검증한다.

프로덕션에 실제 NAS 쓰기나 세션 만료 상태 변경을 수행하지 않았다. 쓰기를 재시도하거나 관련 없는 사용자 세션을 무효화하지 않는다. 과거 NAS_API_ERROR만으로 NAS 숫자 코드를 사후에 확정할 수는 없다. 새 로그는 재발 시 해당 코드를 보존한다.

브라우저 근거: Aside에서 로그인 유지 비활성/활성 상태로 모의 만료를 실행하면 로그인 화면으로 돌아갔고 /api/auth/me는 401을 반환했다. 그래프의 401도 이제 로그인 화면으로 돌아간다. 프로덕션에서 새로 로그인한 뒤 NAS 쓰기 없이 메모장과 노트를 성공적으로 읽었다. 브라우저는 이전에 캐시한 HTML도 재사용했다(이전 스크립트 URL이 캐시를 우회해 받은 index와 달랐다). 이제 HTML은 Cache-Control:no-store를 전송한다. 기존 캐시 사본에는 업데이트 후 강력 새로고침이 한 번 필요하다.

독립 검토에서 토큰 누락 응답이 교체된 쿠키를 삭제할 수 있음을 발견하여 수정하고 테스트를 추가했다. 이미 만료된 상태에서 명시적으로 로그아웃하면 로컬에서는 완료로 처리하며, 다른 로그아웃 실패에서는 초안을 보존한다. 테스트는 자격 증명/토큰과 쿼리 문자열이 캡처된 로그에 절대 나타나지 않는지 검증한다. 타임스탬프, API 작업, 상태 및 소요 시간은 서버가 생성한 요청 ID로 연결된다.

최종 검증: 백엔드 238개 테스트, 프런트엔드 49개 테스트, 프로덕션 빌드 및 Compose 검증을 통과했다. 게시된 linux/amd64와 linux/arm64 매니페스트를 모두 받아 실행했다. 설치 버전 0.4.2, HTTP/HTTPS 로그인/읽기, 로그인 유지 상태에서 NAS 재로그인 실패 ->401, 세션 폐기/쿠키 삭제, 요청 ID, 무효화 로그 출력, HTML no-store 및 UID/비공개 모드 검사를 모두 통과했다. 이미지 인덱스 sha256:265803b7ff8bcd4f28d48010d9d5c28b18d812e1f659d936ec010837a02d012c. 프로덕션 서비스 배포는 변경하지 않았다.
