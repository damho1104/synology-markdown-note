# Synology Markdown Note 1.2.11 (빌드 22)

[English](1.2.11.md) | **한국어**

기존 로컬 DB에 누적된 FTS 검색 인덱스를 자동 정리하고, SQLite 자동 백업과 시작 장애 시 복구 화면을 추가합니다. 수정 이력은 삭제하거나 보관 개수를 제한하지 않습니다.

## 변경 사항

- 검색 텍스트가 동일한 저장에서 인덱스를 다시 쓰지 않습니다. 이전 REPLACE 저장으로 발생한 고아 행, 누락·불일치 문서 및 FTS 내부 무결성을 확인하고 이상이 있으면 검증된 DB 백업 후 인덱스를 재구성합니다.
- 정리 후 VACUUM과 WAL 체크포인트로 DB 파일 공간을 회수합니다. 회수 실패 이후에도 빈 페이지가 4 MiB 이상이고 DB의 25% 이상이면 다음 시작에서 백업 후 재시도합니다.
- SQLite Backup API로 WAL의 미반영 변경도 포함하는 계정별 일관된 스냅샷을 생성합니다. 앱 시작과 실행 중 6시간 간격으로 확인하고 백업 간격은 12시간입니다. 일별 7개·주별 4개 기준으로 보관합니다.
- 시작 시 DB를 열 수 없거나 백업이 있는데 DB가 사라진 경우 빈 DB로 초기화하지 않고 복구 화면을 표시합니다. 사용자가 계정별 백업을 선택하고 확인하면 복구합니다.
- 복구 전 DB·WAL·SHM을 recovery 폴더에 보존합니다. 복구본 초기화가 실패하면 기존 DB를 되돌리며, 되돌리기 실패 시 원본과 복구본의 보존 위치를 안내합니다.

## 검증

- Swift 전체 306개 테스트 / 31개 스위트, Python CLI 100개 테스트.
- DB 유지보수 테스트 13개: 기존 인덱스 정리, 파일 공간 회수 재시도, 백업·복구·롤백, 계정 격리, 수정 이력·첨부 참조·전송 대기 작업 보존.
- 합성 누적 DB에서 8,376,320 → 180,224바이트로 축소를 확인했습니다. 운영 DB의 감소량을 의미하지 않습니다.
- 로그인 회귀 테스트에서는 세션 만료 요청과 예약 업로드가 겹치지 않도록 예약 작업을 취소하고 완료를 기다립니다.

## 백업 범위 및 배포

자동 백업은 SQLite DB만 포함합니다. assets의 첨부파일 원본과 Keychain 로그인 정보는 포함하지 않습니다. 복구 시 기존 assets 폴더를 유지합니다. 백업 시점 이후의 로컬 편집·전송 대기 내용은 복구본에 없을 수 있으며, 정리 전 백업 파일은 보관 정책에 따라 별도 공간을 사용합니다.

macOS 14+ Apple Silicon용 DMG·ZIP 및 Ubuntu 22.04/24.04 amd64·macOS arm64 CLI를 함께 배포합니다. 앱은 기존 로컬 인증서로 서명하며 Developer ID 서명·Apple 공증은 포함하지 않습니다. 릴리스 게시는 설치된 앱 교체나 운영 DB 정리를 수행하지 않습니다.
