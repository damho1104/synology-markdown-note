# Synology Markdown Note 1.2.11 (Build 22)

**English** | [한국어](1.2.11.ko.md)

Automatically cleans up accumulated FTS search indexes in existing local databases, and adds automatic SQLite backups and a recovery screen for startup failures. Revision history is neither deleted nor limited in count.

## Changes

- Avoid rewriting the index when saving unchanged search text. Check for orphan rows caused by earlier REPLACE saves, missing or mismatched documents, and internal FTS integrity; if issues are found, rebuild the index after creating a verified DB backup.
- Reclaim DB file space after cleanup using VACUUM and a WAL checkpoint. If reclamation fails and free pages still total at least 4 MiB and at least 25% of the DB, back up and retry on the next startup.
- Use the SQLite Backup API to create consistent per-account snapshots that include changes still in the WAL. Check at app startup and every 6 hours while running; the backup interval is 12 hours. Retain 7 daily and 4 weekly backups.
- If the DB cannot be opened at startup, or the DB is missing while backups exist, show a recovery screen instead of initializing an empty DB. Restore after the user selects and confirms a per-account backup.
- Preserve the DB, WAL, and SHM in a recovery folder before restoration. If initialization of the restored copy fails, roll back to the existing DB; if rollback fails, show the preserved locations of the original and restored copies.

## Validation

- Full Swift suite: 306 tests / 31 suites; Python CLI: 100 tests.
- 13 DB maintenance tests: existing index cleanup, file space reclamation retries, backup, recovery and rollback, account isolation, and preservation of revision history, attachment references, and pending transfer jobs.
- Confirmed reduction from 8,376,320 to 180,224 bytes in a synthetic accumulated DB. This does not represent the reduction in a production DB.
- Login regression tests cancel scheduled jobs and wait for completion so that session expiration requests do not overlap scheduled uploads.

## Backup Scope and Distribution

Automatic backups include only the SQLite DB. They do not include original attachments in assets or Keychain login information. Recovery preserves the existing assets folder. Local edits and pending transfers after the backup time may be absent from the restored copy, and pre-cleanup backups consume separate space under the retention policy.

Distributes DMG and ZIP files for macOS 14+ Apple Silicon alongside the CLI for Ubuntu 22.04/24.04 amd64 and macOS arm64. The app is signed with the existing local certificate; Developer ID signing and Apple notarization are not included. Publishing the release does not replace the installed app or clean up the production DB.
