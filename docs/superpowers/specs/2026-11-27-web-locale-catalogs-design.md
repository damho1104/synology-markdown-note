# 웹 번역 리소스 설계

## 범위

Synology Note 웹의 번역을 고정 키와 언어별 리소스로 관리한다. 현재 한국어와 영어 문구 및 웹의 언어 선택 동작을 유지한다. 시스템·브라우저 언어 선택은 UI 및 새로 만드는 항목의 앱 기본값에 적용한다. 이미 저장된 메모장과 메모 이름·본문은 보존한다.

## 방식

현재 번역 함수를 확장하면 의존성을 추가하지 않고 문구를 분리할 수 있다. i18next를 사용하면 언어 폴백, 치환 변수, 복수형 처리를 라이브러리가 맡고, 기존의 `t()` 호출 형태를 유지할 수 있다. 웹은 i18next를 사용한다.

- 화면과 오류 처리 코드는 `auth.signInTitle` 같은 의미 있는 고정 키를 사용한다. 같은 키로 한국어와 영어를 조회한다.
- `locales/ko/`와 `locales/en/` 아래에 기능별 JSON을 둔다. 시작 안내, API 오류 문구와 CodeMirror 문구도 카탈로그에 포함한다.
- 지원 언어는 프런트엔드와 백엔드가 읽는 공유 JSON에 등록한다. 백엔드 패키지와 Docker 빌드가 이 파일을 함께 포함하도록 확인한다. 새 언어는 기능별 리소스를 추가하고 공유 목록에 한 번 등록해 활성화한다.
- `WEB_DEFAULT_LANGUAGE=auto`는 브라우저 선호 순서에서 지원 언어를 고른다. 고정값은 사용자 브라우저와 관계없이 적용한다. 운영자 설정을 가져오는 과정의 재시도는 유지한다. 선택 가능한 언어가 없으면 영어를 사용한다.
- 새 앱 버전이 이전 세션 저장소의 오류 문구를 읽을 수 있도록 기존 보관 초안과 첨부 상태를 확인한다. 번역 키가 사용자 데이터나 기계용 오류 코드를 대신하는 일은 방지한다.

## 검증

등록 언어별 번역 파일, 사용 키, 중복 키, 메시지 치환 변수의 호환성을 테스트한다. 영어·한국어 강제 설정과 브라우저 선호 언어, 초기 설정 재시도, 새 메모 기본 제목과 기존 제목 보존을 확인한다. 임시 테스트 카탈로그를 등록해 프런트엔드와 백엔드에서 같은 언어를 선택할 수 있는지 검증한다. 최종 프런트엔드·백엔드 테스트, 프로덕션 빌드, 추가 의존성을 포함한 npm 감사를 실행한다.
